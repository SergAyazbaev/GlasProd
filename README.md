# Бот-координатор заселения

ИИ-бот для сайта аренды [whdoctor.kz](https://whdoctor.kz), который сопровождает клиента от момента подтверждения бронирования до успешного заселения.

Это не просто чат-бот поддержки. Система должна управлять процессом заселения, отслеживать этапы, отправлять инструкции и напоминания, а также подключать оператора при возникновении проблем.

---

## 1. Цели проекта

Основные задачи бота:

- Автоматически реагировать на новые бронирования.
- Поддерживать связь с клиентом до, во время и после заезда.
- Собирать необходимую информацию о поездке.
- Отправлять инструкции по заселению.
- Контролировать выполнение этапов заселения.
- Обнаруживать проблемы и передавать их оператору.
- Хранить историю взаимодействий и изменений статусов.
- Снижать нагрузку на администраторов и операторов.

---

## 2. Как работает система

### Основной сценарий

1. Получение бронирования.
2. Установление связи с клиентом.
3. Подготовка к заезду.
4. Координация заселения.
5. Подтверждение успешного заезда.
6. Обработка проблем и эскалация оператору.

### Подробное описание этапов

#### 1. Получено бронирование

RealtyCalendar отправляет webhook на backend.

Backend:

- принимает событие;
- проверяет структуру и тип события;
- сохраняет бронирование;
- определяет объект недвижимости;
- создаёт процесс заселения;
- передаёт событие боту.

#### 2. Связь с клиентом

Бот связывается с клиентом через согласованный канал:

- Telegram;
- WhatsApp;
- чат на сайте;
- другой подключённый канал.

Бот:

- приветствует клиента;
- подтверждает основные детали бронирования;
- объясняет дальнейшие действия;
- при необходимости запрашивает контактные данные.

#### 3. Подготовка к заезду

Бот отправляет:

- адрес объекта;
- дату и время заезда;
- правила проживания;
- инструкции по получению ключей;
- информацию об оплате;
- необходимые документы или ссылки.

Также бот уточняет планируемое время прибытия.

#### 4. Заселение

В зависимости от объекта бот координирует:

- получение ключей;
- получение кода от ключницы;
- открытие умного замка;
- встречу с представителем;
- связь с администратором.

#### 5. Подтверждение заселения

После предполагаемого времени заезда бот уточняет:

> Вы успешно заселились?

Возможные ответы:

- Да, всё хорошо.
- Не могу попасть в квартиру.
- Есть проблема.
- Нужна помощь оператора.

Результат сохраняется в системе.

#### 6. Проблема

Если клиент сообщает о проблеме, бот:

1. Определяет тип проблемы.
2. Создаёт задачу оператору.
3. Назначает ответственного.
4. Уведомляет клиента о принятии обращения.
5. Отслеживает решение проблемы.
6. Закрывает задачу после подтверждения.

## 3. Контрольные этапы и напоминания

| Этап            | Действие бота                | Что фиксируется          |
|---              |---                           |---                       |
| Бронирование    | Приветствует клиента         | Бронирование создано     |
| За 3 дня        | Отправляет напоминание       | Сообщение отправлено     |
| За 1 день       | Запрашивает время прибытия   | Планируемое время заезда |
| Подготовка      | Отправляет инструкции        | Документы, оплата, готовность |
| Заезд           | Отправляет адрес и данные доступа | Ключи, код или встреча |
| После заезда    | Уточняет результат           | Успешно или проблема     |
| Проблема        | Передаёт обращение оператору | Открытая задача          |

Количество дней и время напоминаний должны настраиваться отдельно для каждого объекта недвижимости.

## 6. Модель состояния заселения

Каждое бронирование получает собственный workflow.

```text
booking_created
      │
      ▼
awaiting_guest_contact
      │
      ▼
awaiting_arrival_time
      │
      ▼
pre_checkin
      │
      ▼
awaiting_checkin
      │
      ├── guest_arrived
      │       │
      │       ▼
      │   checkin_confirmed
      │
      └── problem_reported
              │
              ▼
          operator_assigned
              │
              ▼
          problem_resolved
```

### Описание статусов

| Статус | Описание |
|---|---|
| `booking_created` | Бронирование получено |
| `awaiting_guest_contact` | Ожидается установление связи с клиентом |
| `awaiting_arrival_time` | Ожидается время прибытия |
| `pre_checkin` | Выполняется подготовка к заселению |
| `awaiting_checkin` | Ожидается подтверждение заселения |
| `guest_arrived` | Клиент сообщил о прибытии |
| `checkin_confirmed` | Заселение подтверждено |
| `problem_reported` | Клиент сообщил о проблеме |
| `operator_assigned` | Назначен ответственный оператор |
| `problem_resolved` | Проблема решена |

Состояния должны храниться в MongoDB, а не только в памяти приложения.

## 8. Обработка нового бронирования

### Сценарий

```text
RealtyCalendar
      │
      ▼
POST /api/realtycalendar/webhook
      │
      ▼
Проверка JSON
      │
      ▼
Проверка action и status
      │
      ▼
Поиск объекта по realty_id
      │
      ├── Объект найден
      │       │
      │       ▼
      │   Сохранение брони
      │       │
      │       ▼
      │   Создание checkin_workflow
      │       │
      │       ▼
      │   Создание первых задач
      │
      └── Объект не найден
              │
              ▼
          Ошибка сопоставления
              │
              ▼
          Задача оператору
```

### Требования к обработчику

- Проверять входные данные.
- Поддерживать идемпотентность.
- Не создавать дубли при повторной доставке webhook.
- Сохранять исходное событие для аудита.
- Логировать ошибки.
- Разделять приём webhook и выполнение фоновых задач.
- Использовать повторные попытки для временных ошибок.

## 9. Взаимодействие с клиентом

### Пример: сообщение о времени прибытия

Клиент:

> Добрый день, я приеду 2 октября примерно в 18:00.

Бот должен:

1. Определить намерение: сообщение времени прибытия.
2. Извлечь время: `18:00`.
3. Сохранить значение в workflow.
4. Перевести процесс на следующий этап.
5. Отправить подтверждение клиенту.

Ответ бота:

> Спасибо! Зафиксировали планируемое время прибытия — 18:00 2 октября. Ближе к заезду отправим необходимые инструкции.

### Пример: проблема с доступом

Клиент:

> Не могу открыть дверь, код не работает.

Бот должен:

1. Распознать проблему доступа.
2. Создать срочную задачу оператору.
3. Уведомить клиента, что обращение принято.
4. Передать оператору необходимые данные.
5. Не закрывать задачу до решения проблемы.

## 10. Правила безопасности и надёжности

Система должна учитывать следующие требования:

- Не передавать коды доступа неавторизованным лицам.
- Проверять связь клиента с конкретным бронированием.
- Не хранить секреты в исходном коде.
- Использовать переменные окружения.
- Ограничивать доступ операторов по ролям.
- Вести журнал действий.
- Защищать webhook от поддельных запросов, если RealtyCalendar предоставляет механизм проверки.
- Не отправлять повторно одноразовые коды без необходимости.
- Учитывать часовой пояс объекта недвижимости.
- Обеспечивать повторную обработку событий без дублирования.
